# 有界动画：动作动画与移动补间，没有常驻循环

ADR 0006 规定“不做补间与常驻动画，画面停在每个 Tick 的状态”，出发点是省电。用户澄清省电的尺度是相对官方客户端（在用户的 Mac 上约 20 W）：官方耗电的根源是渲染循环永不停止——每帧重画、常驻空闲动画、页面隐藏时也不停，而不是动画本身。我们改为允许**有界动画**：每个新 Tick 触发的动作动画（Action Animation）与移动补间（Movement Tween），时长按 Tick 间隔的比例（照官方渲染器），播完回到静止画面；动画期间按显示器刷新率渲染，不限帧。

底线不变：没有进行中的动画时不渲染；页面隐藏或 Room View 不在屏幕上时完全停止，回到画面时不补播；没有常驻的空闲循环（例如塔的空闲转动、沼泽流动、光晕呼吸）。

## Considered Options

- **维持静止画面**：最省电，但用户需要看清战斗与劳作。
- **整体嵌入官方渲染器的动画**：被 ADR 0006 否决的理由仍然成立。
- **动画期间限帧（如 30 fps）**：节省有限；在“相对官方省电”的尺度下不值得牺牲流畅度。

## Consequences

- 取代 ADR 0006 “不做补间与常驻动画”一句及其后果“画面停在每个 Tick 的状态”。
- Room View 需要知道 Tick 间隔：Live 用 Top Bar 的实测值，Replay 由播放速度算出，下限 0.1 秒。
- 动画可以在显示选项中关闭；系统要求减少动态效果时默认关闭。
- 有 creep 在走的房间里，画面几乎一直在渲染（仍受页面可见性约束）。
